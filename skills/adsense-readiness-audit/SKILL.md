# AdSense 审核准备度审计

## 目标

将公开站点、站点代码和用户提供的 AdSense 通知，与 Google 当前官方要求逐项比对。给出可复核的风险判断和修复顺序，不承诺 Google 一定批准。

## 开始前

1. 完整读取 [references/policy-baseline.md](references/policy-baseline.md) 和 [references/domain-history.md](references/domain-history.md)。
2. 若用户说明使用 Cloudflare，或 DNS/响应头/页面显示 Cloudflare、CDN、WAF、挑战或 `520`–`526`，完整读取 [references/cloudflare-cdn.md](references/cloudflare-cdn.md)。
3. 确认任务属于以下哪一种：申请前体检、拒审诊断、重新送审检查、Policy Center 合规排查、域名历史专项检查。
4. 收集站点 URL；若已有拒审邮件、站点状态、Policy Center 文案或截图，一并使用。不要因缺少后台信息而停止公开站点审计，将账户侧项目标为“未知”。
5. 确认审计对象是普通内容网站。若是 YouTube、Blogger 或其他 host partner，说明其申请流程不同，只审计仍适用的发布商政策。
6. 先在 IANA 保留域名和 Special-Use Domain Names 中核对目标。若域名不可注册/转让、不是公网生产域名或用户不可能控制，直接将所有权/用途判为 P0，仍给出简短历史和现场证据，但停止没有价值的深度内容审计。

## 保持政策新鲜度

正式审计时优先浏览 Google 官方来源：

1. 检查政策变更日志是否有基线日期之后的新条目。
2. 打开与本次问题直接相关的官方页面，而不是只依赖搜索摘要。
3. 若官方页面与本地基线冲突，以当前官方页面为准，并指出变化。
4. 若无法联网，使用基线完成审计，但明确写出“未在线复核，政策基线日期为 2026-08-12”。

只把 Google AdSense Help、Google Publisher Policies Help、Google Search Central、Google Terms 或其明确链接的标准作为“官方要求”。社区文章、代理经验和 SEO 博客只能标为“经验建议”。

## 执行审计

### 1. 确定覆盖范围

覆盖首页、主要导航、代表性内容页、分类或列表页、隐私页，以及登录、搜索、工具、下载、UGC 或联盟营销等特殊模板。记录实际检查的 URL 和未覆盖范围。Google 可能检查整个站点，不要只看申请 URL。

若用户提供的是代码仓库，先定位路由、模板、robots.txt、广告代码、隐私文案和内容来源；能安全启动站点时再做浏览器检查。

### 2. 运行技术探测

有 Python 和公网访问时，在本 Skill 目录下运行（或把 `scripts/site_probe.py` 替换为其绝对路径）：

```bash
python scripts/site_probe.py https://example.com --max-pages 30 --format markdown
```

先用 `python --version` 预检解释器；若命令指向 Microsoft Store 占位符或不可用，依次尝试 `py -3`、`python3`、工作区提供的 Python 绝对路径。仍不可用时不要停止审计，改用浏览器和 HTTP/DNS/RDAP/Wayback 页面手工完成同一证据清单，并在覆盖范围中记录“脚本未运行”。

将脚本输出只视为技术证据。它能探测可达性、重定向、robots.txt、ads.txt、AdSense 代码、页面标题、语言、近似正文量、站内链接、常见信任页入口，以及 Cloudflare 响应头、Challenge Page 和 `520`–`526` 线索；它不能判断原创性、版权、内容真实性、合法性或最终审核结果。

若发现或已知使用 Cloudflare，按 `references/cloudflare-cdn.md` 补查裸域/`www`、HTTP/HTTPS、代表页、`robots.txt`、`ads.txt`、验证页、Cloudflare Security Events/Logs、SSL/TLS、WAF/Bots、Access、Workers/Redirects 和缓存。不要把模拟 Google User-Agent 的结果当成真实爬虫证据；优先使用 AdSense 后台、Cloudflare 事件和源站日志中的实际请求。

对于依赖 JavaScript、Cookie 同意、地理位置、登录状态或交互的页面，使用浏览器补查桌面端和移动端。不要把脚本未发现某元素直接当作元素不存在。

同时运行有界域名历史探测：

```bash
python scripts/domain_history_probe.py example.com --wayback-snapshots 4 --format markdown
```

它收集当前 RDAP 注册事件、DNS、HTTP/HTTPS 跳转、TLS 和 Internet Archive 时间点样本。它不能证明历史所有者身份、完整收录、Google 处罚、安全清白或 AdSense 结果。脚本失败或无快照只能记为“无法核实”，不能记为“没有历史问题”。

### 3. 审查域名历史和旧站残留

严格按 `references/domain-history.md` 建立“域名前身用途时间线”，至少回答：

- 最早、关键变化点和最近历史快照分别是什么时间、标题、主题、语言和站点类型；是否发生明显行业或用途切换。
- 当前 RDAP 能证明哪些注册事件、状态、注册商和权威 DNS；哪些字段被隐去。不得把当前创建日期直接当成域名首次存在日期或所有权变更日期。
- 旧 URL、旧子域、旧索引结果、旧 sitemap、外链落地页是否仍返回垃圾内容、软 404、批量跳转、被黑页面、成人/赌博/药品等无关内容。
- HTTP/HTTPS、`www`/裸域、移动端、地区、来源和 User-Agent 是否出现不一致内容、意外跨域跳转、伪装或恶意下载。
- Google Safe Browsing 公开状态是否有警告；用户提供 Search Console 时，检查“安全问题”和“手动处置”报告及历史消息。
- 购买过期域名是否主要为了利用旧排名信号承载低价值内容。域名被重新使用、题材改变或存在旧快照本身不是违规；只有符合当前垃圾政策定义且有证据时，才报告“过期域名滥用”。

将每条域名结论标记为 `当前事实`、`历史快照`、`第三方信号`、`用户后台证据` 或 `推断`，并给出证据日期与置信度。历史快照中的旧业务不能证明当前申请人曾经营该业务。

### 4. 人工评估内容和体验

逐个模板检查：

- 判断页面是否提供清晰、完整、可归因的发布者内容，而非模板、占位符、标题集合或广告容器。
- 比较站内相似页面，识别复制、轻微改写、批量生成、聚合嵌入和关键词门页；寻找独到经验、分析、数据、工具价值或编辑增量。
- 检查菜单、下拉、面包屑、分页、搜索、下载和关键按钮是否可读、可点击、目标准确，且没有死链、误导跳转或妨碍内容的弹窗。
- 检查用户生成内容、评论、外链、嵌入内容和站内其他广告；发布商对页面上这些内容同样负责。
- 检查站点及页面主要语言是否受支持。

不要发明文章数、单篇字数、流量或域名年龄阈值。正文量只能用来发现需要人工复查的页面，不能单独决定通过或拒绝。

### 5. 检查完整阻塞面

逐项检查并登记以下十四个通道；任何通道都不得因公开页面上“没看见问题”就自动记为通过：

1. 账户资格：年龄、重复账户、历史停用、身份/付款信息、支持语言、制裁或产品适用性。
2. 域名所有权：正确域名、HTML 控制权、AdSense 代码/meta、Search Console 或 ads.txt 验证、站点在账户中的状态。
3. 上线与抓取：DNS、状态码、登录墙、robots、Cloudflare/CDN/WAF、Challenge、`520`–`526`、Bot/Access/地域/IP 限制、SSL、缓存、Workers/重定向和 JavaScript 渲染。
4. 域名历史：前身用途、过期域名滥用、旧垃圾路径/子域、用途和主机冲突。
5. 安全信誉：Safe Browsing、Search Console 安全问题、恶意软件、被黑内容、伪装、社会工程和意外跳转。
6. 搜索垃圾：规模化低价值、抓取、门页、薄联盟、关键词/隐藏文本、链接垃圾、站点声誉滥用和 UGC 垃圾。
7. 内容价值：原创增量、完整性、模板/占位页、广告与发布者内容比例。
8. 内容政策：Google Publisher Policies 的全部禁止类别。
9. 用户体验：导航、死链、误导按钮、弹窗/遮挡、下载行为、移动端和主要模板一致性。
10. 流量：自点、诱导、奖励、机器人、流量交换、垃圾邮件和购买流量质量。
11. 广告实现：代码连接、误触、不适当位置、广告伪装和 ads.txt 授权。
12. 隐私与同意：必需披露、标识符/精确位置、儿童内容、EEA/英国/瑞士 CMP 与适用法律。
13. 限制内容：单列 Google Publisher Restrictions，不与禁止内容混淆。
14. 后台状态：Policy Center、Sites、拒审原文、抓取错误、待处理审核、手动处置和历史通知。

特别注意：

- 将 Google Publisher Policies 的禁止项与 Google Publisher Restrictions 的限制项分开。限制项通常意味着广告需求受限，不等于政策违规。
- 检查账户是否满足年满 18 岁、一个发布商一个 AdSense 账户、信息真实完整、站点所有权可验证等条件。
- 将隐私政策视为明确的发布商政策要求，检查 Google 广告数据、Cookie/标识符、第三方使用及退出个性化广告等披露。
- 只有服务 EEA、英国或瑞士用户时，才把 Google 认证 CMP/TCF 要求列为区域条件项；同时提醒适用法律可能要求更广泛的同意机制。
- 将 ads.txt 标为“强烈建议但非普遍强制”；若站点已经使用 ads.txt，则其中必须正确授权该发布商。

### 6. 分级结论

使用以下级别，不使用含糊的百分制：

- `P0 硬性阻塞`：有明确官方不合规、无法访问或无法完成所有权验证的证据；送审前必须修复。
- `P1 高拒审风险`：原创价值、内容完整性或导航体验明显不足，但 Google 没有公开机械阈值。
- `P2 条件项`：只在特定地区、内容、流量或实现方式下适用，或需要用户提供账户侧证据确认。
- `P3 优化项`：有助于信任、体验或收益，但不能表述为 Google 的普遍审核门槛。

只允许以下总体判断：

- `无法充分评估`：关键页面无法访问或覆盖严重不足。
- `暂不建议送审`：存在 P0。
- `整改后再送审`：没有已证实的 P0，但存在显著 P1 或待确认的关键 P2。
- `具备送审条件`：在已检查范围内未发现 P0，P1 已处理；仍需声明“非批准保证”。

## 输出格式

按以下顺序输出：

1. **结论**：总体判断、最关键的 1–3 个理由、非批准保证。
2. **覆盖范围**：检查方式、URL/模板数量、账户侧资料、历史来源、未覆盖项和日期。
3. **Cloudflare/CDN 证据**：仅在检测到或用户声明使用时输出，列出检测线索、挑战/错误 URL、DNS/TLS/重定向/缓存结果、实际爬虫后台证据和未覆盖配置；使用 Cloudflare 本身不得列为问题。
4. **域名前身用途时间线**：`时间/区间 | 来源 | 当时标题/用途 | 变化 | 置信度 | 与当前风险的关系`；无可靠快照时明确写“无法核实”。
5. **完整阻塞项登记表**：列出上述十四个通道，使用 `已证实阻塞 / 高风险 / 条件项 / 未发现 / 无法从公开面核实 / 不适用`，并给出证据。`未发现`不等于 Google 已确认通过。
6. **发现表**：`级别 | 性质（官方要求/官方质量信号/条件项/经验建议） | 问题 | 现场证据 | 官方依据 | 修复动作 | 复验方法`。
7. **优先整改清单**：按依赖关系给出最短可执行顺序；先 P0，再 P1。
8. **送审前复验**：列出能明确验证完成的检查，不重复整份报告。
9. **仍需用户确认**：只列后台、账户、流量来源或地域覆盖等无法从公开站点证明的事项。

给每个事实结论附 URL、页面位置、响应状态、可见文本摘要或配置路径。将推断明确写成推断。若没有证据，不下确定结论。

## 防止常见误判

- 不宣称必须有固定文章数、固定单篇字数、最低流量、最低域名年龄或必须先被 Google 全量收录；Google 未公开这些普遍硬门槛。
- 不把域名年龄、注册商、隐私保护、换过主题、旧快照或购买二手域名单独判为阻塞。寻找当前残留、操纵目的和官方后台证据。
- 不把 Wayback Machine 没有快照解释成域名从未使用；归档可能不完整、被阻止或被移除。
- 不把 RDAP 的 `registration` 事件解释成域名最早创建或最近易主的绝对证据；重新注册、注册局迁移和字段隐去都会改变可见结果。
- 不用第三方“域名信誉分”单独下 P0；Google Safe Browsing、Search Console、安全复现和当前页面证据优先。
- 不把 About、Contact、Terms 页面说成所有网站的明文硬性页面要求；它们常能降低发布者身份、用途和用户信任方面的风险。隐私披露则是明确政策要求。
- 不把 ads.txt 说成普遍强制文件；Google 明确称其非强制但强烈建议。若文件存在却未授权发布商，则属于问题。
- 不把 AI 辅助内容本身判违规；判断是否属于批量低价值、复制、误导、无增量或违反搜索垃圾政策的内容。
- 不把受限制内容直接判为禁止内容；解释它可能获得较少或没有广告需求。
- 不只检查首页；Google 明确提示可能检查全站页面。
- 不把使用 Cloudflare、橙云代理、Cloudflare DNS、特定套餐或某个 SSL 模式本身判为风险。只在当前可达性、真实爬虫、连接验证、内容一致性或脚本执行有证据时判级。
- 不替用户提交申请、删除内容或更改生产站点，除非用户明确要求实施。
